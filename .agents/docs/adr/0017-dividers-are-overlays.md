# Insertion dividers are overlays, not flex items

**Status:** Accepted. Supersedes the shown-divider parts of [ADR 0014](./0014-divider-thickness-pinned-inline.md) and [ADR 0015](./0015-dividers-are-layout-neutral.md). Issue #466. Drop handling: issue #347.

Issue #466: shown insertion dividers are real flex items interleaved between row and column children. They take a flex slot, use negative margins of `(gap + thickness) / -2` to cancel their own space, and shift siblings under `justify-content: space-between | around` (about 21 uses in the bundled templates). Because the shown divider moves the child under the cursor, the 30% / 70% edge check can flip-flop and the divider flickers while the pointer moves. Only the "+" button is clickable; clicking the bar itself does nothing.

## Decision

- **Rows and columns render no divider elements inside the flex container.** The `intersperseAndAppend` divider interleaving is removed from `row.tsx` and `column.tsx`, so the children are the only DOM children (plus existing empty-state content). Edit-mode layout is identical to preview for any `gap` and any `justify-content`.
- **The active divider is drawn as an overlay portalled to `document.body`** (like `EditorOverlay`, ADR 0016) and placed from the hovered child's own box via `useElementBox`. A 4px bar with a centered "+" badge, anchored to the hovered child's own edge (start or end along the main axis), so wrapped rows have no ambiguity at line breaks and an overlay cannot cause a row to wrap. The "+" is drawn on a solid round badge in the bar color, so it stays legible on any background. The bar color is sampled from the page under the bar (`measureBackgroundAt`, which looks through editor chrome marked `data-editor-chrome`), not from the overlay's own ancestors: the overlay lives in a portal, so those would always end at the body.
- **`useDividerVisibility(orientation)` keeps the 30% / 70% edge logic, for one axis.** Dividers are keyed by insertion index (the index a component would get). Two neighbouring children share an insertion index, so each visible divider remembers the single child edge the pointer was last near (`{ childIndex, edge }`): exactly one overlay is drawn per insertion point, where the pointer is. A mounted overlay is always drawn: the hook mounts it only while its divider is visible, and the overlay does not hide itself.
- **`useLayoutDividers` owns the divider wiring for rows and columns** (child boxes, add-at-index, overlay rendering). `row.tsx` and `column.tsx` differ only in the `orientation` they pass.
- **A divider lingers for `DIVIDER_HIDE_DELAY_MS` (1000 ms) after the pointer stops being near its edge.** A pending hide keeps its original deadline, so moving around inside the child does not push it back.
- **An overlay holds its divider while the pointer is on it, its popover is open, or it is the drop target** (`holdDivider`, called from the overlay), so the hide timer cannot unmount the bar or popover from under the cursor. A held divider keeps its anchor, so the bar cannot jump away from an open popover. The hold is released on leave, on close, when the drag leaves, and on unmount.
- **Dividers work during a drag.** Browsers fire no mouse events during a drag, so children forward `dragover` / `dragleave` (`EditModeProps.onDragOver` / `onDragLeave`) and `useLayoutDividers` treats them like `mousemove` / `mouseleave`, only while a component is being dragged and never in the layout that is itself being dragged. Only the divider being dragged over (same parent and insertion index) is highlighted as the drop target.
- **A divider's index is an insertion index counted before the move.** `moveComponent` shifts it down by one when the component moves forward within the same parent, and refuses to move a component into itself, a descendant, or a missing parent (those used to drop it from the tree).
- **The whole bar is a real `<button>`** with `aria-label="Add component here"` that opens the component selector popover. The "+" is the visual cue. The button's hit area is wider than the 4px bar (12px: the bar plus 4px each side), which costs no layout because the overlay is out of flow.
- **Removed:** `resolveMainAxisGap`, `getDividerLayoutStyle`, `getDividerThicknessStyle`, the old interleaved `Divider` component, the free-text `gap` parsing, and the pinned-thickness inline styles, along with their unit tests. The `DIVIDER_THICKNESS_PX` constant (now 4px) is retained for the overlay bar, and `useDividerContrastColor` is retained but now samples the page under the bar (`measureBackgroundUnder`, which walked the overlay's own ancestors, is replaced by `measureBackgroundAt`).

## Consequences

- Dividers can no longer shift siblings, so `justify-content: space-between | around` rows, wrapping rows, and columns are layout-neutral in edit mode.
- The free-text `Gap` setting no longer has to be parsed for divider layout; the divider is placed from the child's real box.
- Clicking anywhere on the divider bar (not only "+") opens the component selector and inserts the component at the correct index.
- Unit tests cover the overlay's position math with mocked `getBoundingClientRect`, the visibility hook (linger, hold, anchors), color sampling, the drag path, and `moveComponent`'s index handling; the removed helpers' tests are deleted.
- Known limitations: the bar color is measured when the divider appears, so it does not follow a later change of the section's background. If the window is resized while a divider is showing and the pointer does not move, the bar stays at its old position until it times out or the pointer moves.

## Visual verification

Hover a child's edge in Edit Mode on any bundled template (including `farm-logistics-landing-page` with `justify-content: space-between` rows and a wrapping row): a 4px divider bar appears at the child's edge, does not move surrounding elements, and clicking anywhere on it opens the component selector. Select a component, drag it by its Move handle over a sibling's edge: a divider appears there, is highlighted while hovered, and dropping on it places the component at that position (over a dark section the bar is light).
